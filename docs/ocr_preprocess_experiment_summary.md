# OCR 및 이미지 전처리 실험 요약

담당: 정서현. 실험 코드와 보존된 핵심 출력은 `notebooks/ocr_engine_comparison.ipynb`에 있다.

## 목적과 비교 방법

동일한 validation 이미지에서 CPU OCR 엔진의 날짜 문자열 회수율과 처리시간을 비교했다. 최초 비교는 `labels/labels_300.csv`를 image_id 순으로 정렬한 동일한 10장을 사용했다. EXIF 방향 보정, RGB 변환, LANCZOS 축소를 공통으로 적용하고 모델 초기화 시간과 이미지 추론 시간을 분리했다. 후속 확대 검증은 기존 10장을 포함하고 나머지 라벨에서 random seed=42로 추출한 고정 30장을 사용했다.

날짜 토큰 재현율은 OCR 텍스트의 숫자열에 라벨 날짜의 YMD/DMY/MDY 변형이 포함되는지를 검사하는 스크리닝 지표다. 날짜 선택, 소비기한 판별, 최종 제출 정확도를 측정한 것은 아니다. 완전하지 않은 날짜 라벨은 재현율 분모에서 제외하되 처리시간에는 포함했다.

| 동일 10장 비교 | 날짜 토큰 재현율 | 평균 초/장 |
|---|---:|---:|
| EasyOCR, 입력 긴 변 1600px | 80% | 21.417 |
| PaddleOCR, 최초 구성, 입력 긴 변 1600px | 100% | 42.926 |
| EasyOCR, 입력 긴 변 1000px | 80% | 13.693 |
| PaddleOCR, 입력 1000px / 검출 한도 640px | 100% | 31.883 |

초기 PaddleOCR의 자동 인식 모델 선택과 이후 명시적 한국어 모바일 모델 실험은 구분해야 한다. PaddleOCR은 이 표본에서 회수율이 높았지만 초기 비교에서 속도가 우세하지 않았다.

## 설정 선택과 근거

현재 최선의 **잠정 baseline**은 PaddleOCR의 `PP-OCRv5_mobile_det` + `korean_PP-OCRv5_mobile_rec`, 입력 긴 변 512px, 인식 batch6, `engine.predict(..., text_det_box_thresh=0.7)`, CPU threads=4다. 완성 모델이나 제출 가능한 정확도를 확보한 모델이 아니다.

`text_det_limit_side_len=512`, `text_det_limit_type="max"`, `enable_mkldnn=True`를 사용했다. `use_doc_orientation_classify`, `use_doc_unwarping`, `use_textline_orientation`은 모두 False다. OMP/MKL thread 환경설정도 4다. 모델과 패키지는 설치된 로컬 자원을 사용했다.

| 동일 10장 핵심 실험 | 날짜 토큰 재현율 | 평균 초/장 | 판정 |
|---|---:|---:|---|
| 512px / 모바일 모델 / 기본 batch6 / 임계값 0.6 | 100% | 1.730 | 저장된 출발 기준선 |
| 384px | 100% | 2.499 | 속도 악화로 제외 |
| batch1 | 100% | 3.287 | 속도 악화로 제외 |
| batch12 | 100% | 2.245 | 속도 악화로 제외 |
| 임계값 0.7 | 100% | 1.341 | 잠정 기준 채택 |
| 임계값 0.75 | 90% | 1.240 | 재현율 저하로 제외 |
| 임계값 0.8 | 60% | 0.864 | 재현율 저하로 제외 |

기본 batch가 실제 6이므로 명시적 batch6 실험은 별개 배치 변경 효과로 해석하지 않는다. 설정 비교는 서로 다른 실행 시점의 단일 측정으로, CPU 부하와 초기 실행 효과를 통제한 반복 벤치마크가 아니다.

날짜 정규식과 달력 유효성 검사로 재시도를 결정한 적응형 시뮬레이션도 수행했다. 정답은 재시도 판단에 사용하지 않았다. 1차 시간 전체에 0.7 재시도 시간을 더하면 10장 총시간은 0.7 단독 13.405초, 0.75→0.7은 13.382초, 0.8→0.7은 13.284초였다. 절감은 각각 약 0.17%, 0.90%에 그쳤다. 0.8→0.7의 30장 숫자형 회수율은 23/29였지만 안정성을 확보하지 못해 최종 대안으로 확정하지 않았다.

## 최종 30장: 임계값 0.7 단독

기존 단독 결과 10장과 적응형 실행에서 저장된 0.7 재시도 10장을 재사용하고, 0.7 결과가 없는 10장만 추가 실행했다. 재시도 결과는 두 단계 박스의 연결 순서·좌표 중복·포함 관계를 검증해 분리했다. 해당 이미지 시간에는 `fallback_seconds`만 사용했다. 완료한 OCR 실험은 재실행하지 않았다.

| 지표 | 결과 |
|---|---:|
| 평가 이미지 | 30장 |
| 완전한 날짜 라벨 | 29장 |
| 숫자형 날짜 토큰 재현율 | 22/29 = 75.86% |
| OCR 문자 인식 기준, 아래 수동 검토 포함 | 23/29 = 79.31% |
| 평균 처리시간 | 1.317초/장 |
| 중앙 처리시간 | 1.020초/장 |
| 30장 추론 총시간 | 39.502초 |
| 검출 박스 합계 / 이미지당 평균 | 379 / 12.63개 |
| 3,352장 예상시간 | 73.56분 |

23/29는 평가 코드를 바꿔 산출한 새 지표가 아니다. 숫자형 평가 성공 22장에, OCR이 `04 NOV 2021`을 올바르게 읽은 `002728.jpg` 한 장을 수동 검토로 구분한 수치다. 영문 월 파서는 구현하지 않았으며 이수민 담당자에게 인계한다.

기존 측정과 warm fallback, 신규 측정을 합산했으므로 30장 전체를 새로 실행한 균일한 벤치마크는 아니다. 예상시간은 추론 평균의 선형 환산이며 모델 초기화, 파일 입출력 및 전처리 비용을 포함하지 않는다.

## 실패와 제한사항

OCR 실패 6장은 `001097.jpg`, `000227.jpg`, `000447.jpg`, `000978.jpg`, `000645.jpg`, `000157.jpg`다. 작은 점자형 날짜, 반사, 곡면, 기울기/방향, 숫자 오인식이 관찰됐다. 특히 `000645.jpg`는 `2026-05-13`을 `2026-15-13`으로 읽었다. 이 6장에는 향후 별도의 fallback이 필요하다. 특정 방법의 효과가 검증됐다는 뜻은 아니다.

실패 이미지에만 적용한 자동 대비 보정은 6장 중 회복 0장, 선명화는 `000447.jpg` 1장만 회복했다. 공통 전처리로 채택하지 않았고, 정답을 알고 성공한 전처리를 선택하는 방식의 전체 정확도를 주장하지 않는다.

숫자형 75.86%, 문자 인식 기준 79.31%로 정확도 목표에 미달한다. 예상 73.56분은 **40분 실행 제한을 충족하지 못한다**. 40분에 맞추려면 추론 외 비용을 무시해도 평균 약 0.716초/장 이하가 필요하다. 30장 결과가 불안정해 50장 확대와 전체 300장 실행은 하지 않았다. 영문 월·혼합 구분자·여러 날짜·제조일/소비기한 구분은 남은 문제다.

## 이수민에게 전달할 OCR 형식

이미지별로 원문을 보존한 다음 형태를 전달한다. 아래는 스키마 설명이며 실제 이미지 예측값이 아니다.

```json
{
  "file_name": "example.jpg",
  "input_width": 384,
  "input_height": 512,
  "detections": [
    {"text": "04 NOV 2021", "confidence": 0.98,
     "bbox": [[10, 20], [110, 20], [110, 40], [10, 40]]}
  ],
  "text_det_box_thresh": 0.7,
  "inference_seconds": 1.0
}
```

저장된 `raw_detections_json`의 `box`를 인계 형식의 `bbox`에 대응시킨다. 좌표는 EXIF 보정 후 축소 이미지 기준이며 원본 좌표로 변환하려면 크기와 축척을 함께 보존해야 한다. confidence는 인식 신뢰도이며 날짜가 소비기한이라는 확률이 아니다. 여러 단계 출력은 pass와 임계값을 구분하고 중복 박스를 무조건 합치지 않는다.

`002728.jpg`의 `04 NOV 2021`은 OCR 실패가 아니다. 영문 월을 포함한 날짜 해석 및 평가기 지원을 이수민 작업으로 남긴다. `final_date`와 `date_recalled`는 평가 전용으로, 운영 fallback 조건의 입력에 포함하지 않는다. OCR 원문에서 날짜를 해석하고 최종 소비기한을 고르는 작업은 이 PR 범위 밖이다.

결과 CSV, 라벨, 이미지, 모델은 로컬 `data/`, `labels/`, `weights/`에 있으며 Git에 포함하지 않는다. 새 OCR 실행이나 패키지 설치 없이 기존 결과를 정리했다.
